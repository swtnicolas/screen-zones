# ScreenZones

ScreenZones is a KWin script (Plasma 6, Wayland) that splits displays into fixed zones that behave like independent monitors. Each display is enabled on its own and shows a layout of zones; a window on an enabled display belongs to one zone, keeps its own size and position inside it and never crosses into another zone; it changes zone only by a tab drag, a rule or a move to another display. Apps marked free are never tracked. Each zone has a tab bar listing its windows. QML and JavaScript only, loaded into KWin's process.

## Layout

- `package/` — the KPackage (`KWin/Script`, `declarativescript`), installed as `~/.local/share/kwin/scripts/local.screenzones`.
  - `contents/code/geometry.js` — the pure model: zones as display fractions, `place` (full, bar and content rects for a bar side, abutting), `margins`, `widened` (an opened side bar), `resolve` (falls back to the nearest earlier letter, so C lands in B on two columns), `zoneAt`, `covers`, `visiblePart`, `gesture`, `walls` (the display edges another display borders along a zone), `contain`, `arrive`, `centered`, `target` (the placement rule), `tabWidths`, `dividers`, `uncovered` (divider lines minus the bars), `moving`, `splitting`, `removing`, `relabel` (letters zones in reading order), `edgeMoves` and `pressPoint`.
  - `contents/code/store.js` — the pure state: displays (layout name, `draft`, its unsaved zones, and `tabsAt`, its own bar side), layouts (a zone may carry its own bar side, `tabsAt`, which `copy` keeps through every edit and a split hands to both halves), rules, free apps and last zones per set of displays. "Una columna" (`single`) is the only built-in layout and is never stored.
  - `contents/ui/main.qml` — the manager: persistence, one surface per enabled output, tracked windows by `internalId`, event wiring, placement, gestures, the bars, the menus and the editor sessions.
  - `Bar.qml` (per-zone tab bar, a row on top or bottom or a column of rows on either side; the active tab and the tab under the pointer carry minimize, maximize or restore, and close buttons drawn with the icon theme's `window-*` icons, when the tab shows its title, is wide enough and is not minimized; a button acts on its own tab's window), `Editor.qml` (zone editor), `Dialog.qml` (name prompt and confirmation), `Badge.qml` (size labels), `Shade.qml` (divider lines and the drop highlight).
- `plasmoid/` — the tray widget (`Plasma/Applet` `local.screenzones`, a notification-area item enabled by default), drawn with `contents/images/tray.svg`: a blue block and two gray ones. A click asks kglobalaccel to invoke the script's menu action.
- The app icon is the repo's master `assets/icon/AppIcon.svg`, installed into the hicolor theme as `local.screenzones`, the `Icon` of both packages. `install.sh` takes it from `assets/` beside its folder in the packaged installer, or from the repo root.
- `tests/` — `node:test` unit tests for the two JS libraries; `load.mjs` evaluates a library in a `vm` context, since QML JS libraries have no exports. `tests/e2e/harness.mjs` boots the nested KWin (`session` seeds `screenzonesrc`; `xwayland: true` starts Xwayland, where `openX11` opens the client through `xcb`) and probes it; `x11.mjs` (full screen and maximize of an X11 window, and a resize on a divider with the zone sizes locked), `run.mjs`, `displays.mjs` (a four-zone layout under `kscreen-doctor` scale and position changes on the nested socket) and `sides.mjs` (side bars, a per-display side, the compact column opening on hover, a zone's own side from its letter menu and its tab menu, a display's side from its submenu, freeing an app from its tab, a window taller than its zone overflowing above a bottom bar) and `menu.mjs` (the tray menu, opened through `clickTray` as the widget does, surviving the close of a window that closes on losing focus; a menu item that activates a window) are the end-to-end suites; `client.qml` is their test window (`qml6 client.qml -- title width height minimumWidth minimumHeight domain closes`; a domain makes the app id `<reversed domain>.qml6`, which lets a suite mark it free; `closes` makes it close when it loses focus, like Kickoff; clicks and every change of its width or height print to its stderr, which is how a suite sees every size the client was configured to).
- `tools/drive.c` — input driver over KWin's EIS D-Bus (`org.kde.KWin.EIS.RemoteDesktop.connectToEIS`): `move`, `down`, `up`, `click`, `rclick`, `dclick`, `drag`, `key`, `type`, `wait`.

## Build

`scripts/install.sh` installs or upgrades both packages with `kpackagetool6`, installs the icon, enables `local.screenzonesEnabled` in `kwinrc`, asks KWin to reconfigure and restarts `plasma-plasmashell`, which loads the widget. It then unloads the script and loads a copy of `package/` from a new directory under `$XDG_RUNTIME_DIR`, so the new code runs at once (see Gotchas) without waiting for the next login, and removes the older copies; the tray adds a newly seen widget that is enabled by default on its own. `scripts/uninstall.sh` unloads the script, removes both packages, the icon and the runtime copies, drops `local.screenzonesEnabled` and unregisters the "ScreenZones Menu" action from kglobalaccel; `screenzonesrc` stays. `scripts/package.sh` writes `dist/screenzones-install.sh`, a self-extracting tar of `package/`, `plasmoid/`, the icon and both scripts that runs `install.sh`, or `uninstall.sh` with `--uninstall`. Pushing a `linux-v<version>` tag runs the repository's `.github/workflows/release.yml` inside `linux/`: unit tests, `package.sh` and a GitHub release with the installer attached, which the README downloads with `curl` from the public repo. The version lives in both `metadata.json` files. `scripts/test.sh` runs the unit tests. `scripts/e2e.sh` builds `build/drive` (gcc, libei, libsystemd) and runs the end-to-end suites, each in a `kwin_wayland --virtual` with two 1920×1080 outputs under `dbus-run-session` with a bus configuration that activates no services (portals and secret services activated there crash without a display and leave coredumps), with `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and `XDG_CACHE_HOME` in a temporary directory, so it never touches the session's KWin or configuration. It seeds `screenzonesrc`, loads a fresh copy of the package through `org.kde.kwin.Scripting`, opens `qml6` clients on the nested socket and reads frames through one-shot JS scripts that `print` to KWin's stderr (`QT_FORCE_STDERR_LOGGING=1`). `KEEP=1` keeps the temporary directory and its `kwin.log`. KWin writes `kwinoutputconfig.json` into `XDG_CONFIG_HOME` as it exits, so teardown waits for the clients and for KWin's whole process group to exit before removing the directory; removing it earlier leaves a `config/` behind in `/tmp` on every run.

## Store

QtCore `Settings` writes `~/.config/screenzonesrc`, group `[General]`: `displays`, `layouts`, `rules`, `free`, `last` and `windows` as JSON strings, the general bar side `tabsAt` (default `top`), which a display's own `tabsAt` overrides and a zone's `tabsAt` in its layout overrides in turn, and the menu toggles `borders`, `lockZones` and `zoneFullScreen` (default on), `compactTabs` and `snap`. A display key is the output's manufacturer, model and serial number, plus the connector name when two outputs share them, or the connector name alone when the output reports none. An app is its `desktopFileName`, else its `resourceClass`. `last` holds, per set of enabled displays present (their sorted keys), the display and zone each app's windows were last in. `windows` holds each tracked window's display, zone, preferred size and filled state by `internalId`, which lives as long as the KWin session: it restores windows when the script reloads, and entries no window claims at load are dropped. A display references its layout by name and shows its draft when it has one; moving a divider by resizing a window (with `lockZones` off) only sets the draft, saving the editor changes the layout and drops the drafts of every display showing it, choosing a layout drops the display's draft, renaming updates the references and removing a layout sends its displays back to "Una columna".

## Mechanisms

- Coordinates are KWin's logical global coordinates. A surface's area is `clientArea(MaximizeArea, output, currentDesktop)`, which leaves out the panels; each zone's bar takes a strip along its side (`Store.zoneSide`, else `Store.sideOf`): `barHeight` on top or bottom, `sideWidth` on the left or right, `narrowWidth` there with `compactTabs`; windows live in the content rect beside it. A compact side bar opens to `sideWidth` over the window (`widened`) 150 ms after the pointer enters and closes as soon as it leaves, unless a tab is being dragged, so the content rect never changes. Changing the side or `compactTabs` reflows every window.
- Placement (`place`, `Geometry.target`): a window asks for its preferred size (its size when adopted, then the size a resize by the user or the app leaves it with) clamped to its content rect and to the window's own `minSize` and `maxSize`. `free`, used for the user's own moves and resizes, runs `Geometry.contain`: an edge the zone shares with another zone is a wall, and so is a display edge that another display, enabled or not, borders along the zone (`Geometry.walls`, from every output's geometry); past any other display edge the window stays where it was left while `Geometry.visible` points of it remain in the zone; its top is never above the content rect unless its bar is at the bottom and the window is taller than the content rect. With the magnet (`snap`) `free` clamps inside instead. Both take the content rect and the zone's bar side: an edge next to a bar counts as a divider, so a window never slides under its bar, and an axis larger than the content rect overflows away from the bar, past the display's top when the bar is at the bottom, so a bar is never under its own window. Placements started by ScreenZones (`keep`, `arrive`, `fill`) run `Geometry.arrive`: an oversized axis overflows past the display edge its content rect touches, and a fitting axis is centered only for a window arriving from outside the zone. `filled` is recomputed after every placement.
- Writing `frameGeometry` resizes asynchronously (the client acks the configure), so `request` gives every placement a 500 ms window in which changes that do not match `known` are ignored; `settlePending` checks again when it ends.
- Geometry changes are queued per window and handled 50 ms later (`changeTimer`): KWin emits the maximized or full-screen frame before `maximizeMode` or `fullScreen` changes, and handling it at once would take it for a user resize.
- Gestures: `interactiveMoveResizeStarted` comes after the drag threshold, so the cursor there is not the press point; `Geometry.pressPoint` recovers it at the first `interactiveMoveResizeStepped` from how far the moved edges of KWin's requested geometry travelled. Settling uses the last requested geometry, not `frameGeometry`, which lags while the client acks the last configures. With `lockZones` off, a resize of a window that filled its zone, grabbed within 12 px of a divider, moves that divider for every zone on the line of the display's draft; with it on, every resize is contained. A move stays in its zone unless it ends on another enabled display, which takes it into the zone under the pointer, or outside every enabled display, which releases it. A tab drag carries the window with a 16 ms timer and drops it into the zone under the pointer.
- Maximize toggles filling the zone. On Wayland KWin emits `maximizedAboutToChange` when it accepts the request, before it configures the client, and `maximizedChanged` only when the client commits a frame already at the maximized size; so `maximizeChanging` flags the window and `takeMaximize`, through `Qt.callLater` (after KWin's own resize), calls `setMaximize(false, false)` and toggles, and the client gets a single configure with the final size. On X11 `maximizedChanged` comes inside the request, after KWin has already sent the maximized size to the client, and `maximized` takes it there, so the deferred call runs only while the flag is still set, and `maximized` ignores a maximized state within `pendingTime` of a take. A maximize within 500 ms of a drop (KWin's top-edge maximize) always fills. A tracked window that gets a quick or custom tile is untiled and filled from `requestedTileChanged`, also deferred; `tileChanged` comes on the client's commit.
- Full screen: with `zoneFullScreen` a tracked full-screen window is resized to its zone's full rect, bar strip included; without it, it keeps its display. KWin keeps such a window full screen at that size, the client fills it, and leaving full screen restores the frame it had before, so `known` is left untouched while full screen. A full-screen window counts as filled (`isFilled`): its tab offers the restore, and `toggleFill` takes it out of full screen. KWin sets `fullScreen` only when the client commits its first full-screen frame, already at the display's size; the only earlier signal is `fullscreenGeometryRestoreChanged`, emitted when KWin accepts the request and before its own resize to the display, so `fullScreenRequested` writes the zone rect through `Qt.callLater` and the client's first full-screen frame already has the zone's size (a write inside the signal is overridden). KWin emits that signal only when the saved geometry differs from the last one, so `fullScreenToggled` shifts a window leaving full screen by `restoreNudge` (1/256 px, alternating sign), which KWin keeps unrounded, and entering again from the same frame still emits it. `fullScreenToggled` places the window again on `fullScreenChanged`, in case that signal did not come; on X11 `fullScreenChanged` comes inside KWin's request while geometry updates are blocked, so that placement is the one the client receives. Toggling the option moves every tracked full-screen window between its zone and its display.
- New windows go to the app's rule, else the app's last zone for the current set of displays (on the display under the window when the recorded one is not enabled), else zone A of the display under the window. A rule without a display goes to the leftmost enabled display that has its zone. Rules apply at creation, when set and when a display is enabled.
- Every overlay is an internal QtQuick window created by `overlay` with `createObject(null)`: a `Window` declared inside the root `Item` never shows, since the root has no window. `overlay` makes its title unique, which is how `frameOf` finds its KWin window; `show` compares and writes that KWin frame, not the QWindow's geometry, after `visible = true`, because KWin places internal windows when they are shown. KWin commits an internal window's new size only when it presents a frame at that size (`InternalWindow::present`): an overlay unmapped before then keeps its old frame while its QWindow reports the new geometry, and writing that geometry again is a no-op, so an overlay in use is never unmapped. KWin keeps every internal window in its overlay layer, above all windows (`keepBelow` and `WindowStaysOnBottomHint` are ignored), so `updateCovers` collects for each bar the visible windows that can cover it (popups, notifications, KRunner, free apps, a window being dragged, the zone's own window in full screen) and `showBar` crops the bar's window to the longest stretch along it that none of them overlaps by more than `pixelTolerance` on both axes (`Geometry.visiblePart`, `Geometry.covers`; at fractional scales clients overshoot zone edges by a fraction of a pixel): the window under the cut stretch shows and takes the clicks, and the bar's content keeps the whole bar's layout (`fullWidth`, `fullHeight`) shifted by `offset`. A bar left with no stretch as long as its thickness is `covered` (opacity 0, and `outputOnly`, which KWin's hit test reads on every call). `redraw` drops the bars of a display showing a full-screen window that does not fill a zone. `outputOnly: true` makes KWin's hit test skip a window (badge, drop highlight, divider lines). Divider lines are drawn wherever no bar sits; a bar draws the line on its own left or top edge when that edge is a divider. KWin snaps windows to the bars' edges like to any window.
- Keyboard: KWin delivers keys to an internal window only through the popup grab (`PopupInputFilter`, to the last `Qt.Popup` window added), so the editor and the dialogs are `Qt.Popup`; a click outside them or any window activation closes them.
- Menus are `Qt.labs.platform` menus, which fall back to `QMenu` inside KWin. Every opening builds a new menu tree whose items and submenus are children of its root, and destroys the previous tree; `Menu.clear()` deletes the items itself. A click on the tray icon opens the main menu (per display: zones on or off, layouts, its bar side, the current layout's edit, discard, rename and remove, new; the general bar side and `compactTabs`; borders; the zone size lock, magnet, full screen in the zone, free apps; pause). A secondary click on a zone letter or an empty part of a bar opens it with that zone's bar side on top. Setting a zone's side writes it into its layout and into every draft of that layout; on "Una columna", which is never stored, it sets the display's side. The widget reaches the script through the `ShortcutHandler` action "ScreenZones Menu", registered with no key: it calls `invokeShortcut("ScreenZones Menu")` on kglobalaccel's `/component/kwin` through `org.kde.plasma.workspace.dbus`, the only channel from plasmashell into a KWin script. A secondary click on a tab opens the tab menu (fill or restore, center, minimize, close, its zone's bar side, the app's rule, where "La última zona que usó" means no rule, and freeing the app). A click on a zone letter toggles its sizes. KWin closes every popup on any window activation (`PopupInputFilter`), and an open menu holds the keyboard focus, so a window that closes on losing it hands activation to the next window and takes the menu down: Kickoff, opened with Meta to bring the panel above a full-screen game, does this to the tray menu within 25 ms. A menu closed by an activation within `reopenWithin` of opening, with no item chosen, opens again once at the cursor; `reopenMenu` runs through `Qt.callLater` from both `aboutToHide` and `onWindowActivated`, so the order in which KWin and the script handle the activation does not matter.
- Per-window signals are `Connections` inside an `Instantiator` over `WindowModel`, so unloading the script disconnects them; `Component.onDestruction` destroys every overlay window.
- Output changes open a 3 s hold: windows that move are not released or recorded, and a reflow and adoption run at its end. A panel's geometry change reflows only when it changes a zone area.

## Gotchas

- The tray creates a widget's compact representation only when the widget also has a `fullRepresentation` and its metadata declares `X-Plasma-API` and `X-Plasma-MainScript`; without them it loads the widget and shows nothing. `activationTogglesExpanded: false` keeps a click from opening the empty full representation. plasmashell caches the widget's QML like KWin does.
- KWin's QML engine caches components and JS imports by URL for the life of the process: loading a changed file from the same path runs the old code. A copy at a new path compiles fresh, which is how `scripts/install.sh` and the end-to-end suite load each version; the installed package itself runs from the next login on.
- `import org.kde.kwin` exports `Window` (KWin's window class), which shadows QtQuick's; QtQuick.Window is imported under a qualifier. The root `Item` already has `state` and a `windowChanged` signal, so the manager uses neither name.
- `screenzonesrc` is a QSettings INI file, not KConfig: `kwriteconfig6` reads its quoted JSON strings with `\"` as invalid escapes and writes every value back mangled, and the script then parses no displays and saves empty `displays`, `last` and `windows`. Edit it only with the script unloaded, in QSettings quoting (`"…"` with `\"` and `\\`).
- Internal windows report `pid` -1 and an empty `resourceClass`; that is how the manager skips its own windows and KWin's.
- `kwin.log` can end in a probe's printed line that KWin has only partly written, so the harness reads a probe's answer only from lines that end in a newline (`completeLines`); a half-written line fails `JSON.parse` with "Expected ',' or '}' after property value".
- `Qt.labs.platform` menus inside KWin fall back to `QMenu` without passing exclusive groups on, so a `MenuItemGroup` draws check boxes, never radio buttons.
- plasmashell's scripting (`evaluateScript`) reaches panel and desktop applets but not the applets inside the system tray, so the script has no way to change the widget: the tray icon cannot show the pause.
- Resizing a bar window from inside its `MouseArea`'s exit handler makes Qt Quick deliver a synthetic hover at the last pointer position, which enters the area again and reopens a compact column; `collapse` runs through `Qt.callLater`, once the exit is handled.
- KWin moves pointer focus only on pointer motion: after a popup closes, a click with no motion in between reaches nothing. With EIS input the first key after a popup opens can be lost, so the end-to-end menu steps use the mouse. `drive` waits 100 ms between moving and clicking.
